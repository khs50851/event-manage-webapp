# code-rv

`/code-rv [범위]` — 범위는 경로(예: `components/groups`). 없으면 `app/`, `components/`, `lib/` 전체.

## 워크플로

```
- [ ] 1. 기준 읽기: 루트 CLAUDE.md + 대상 영역의 docs/guides/*.md
- [ ] 2. 대상 파일을 읽고 아래 관점별로 발견 사항 수집(파일:줄 근거 필수)
- [ ] 3. 발견 사항을 "적용" / "제안"으로 분류
- [ ] 4. 적용 항목 수정(호출부까지 함께)
- [ ] 5. npm run check-all 실행 → 실패 시 수정, 못 고치면 되돌리고 "제안"으로 이동
- [ ] 6. git diff --stat으로 확인 후 modified-code.md 작성
- [ ] 7. 채팅에 짧게 보고(커밋은 요청 시에만)
```

Next.js/React/Supabase API가 불확실하면 추측하지 말고 context7로 확인한다. UI가 바뀌면 playwright로 화면을 확인한다.

## 점검 관점

**공통화**
- 같은 JSX·로직·라벨 맵이 여러 파일에 복제돼 있는가(예: 파일마다 `STATUS_LABEL`).
- 이미 있는 `components/ui/*`, `lib/utils.ts`의 `cn()`, `lib/format.ts`를 두고 새로 만든 곳이 있는가.
- 3번째 반복부터 추출한다. 2곳뿐이면 제안으로만 남긴다.

**정합성**
- `lib/types/domain.ts`·`database.types.ts`와 화면·액션의 필드/상태값이 일치하는가.
- 같은 개념이 화면마다 다르게 표시되는가.
- 데이터 계층 위반: 화면이 `lib/data/*` 대신 Supabase를 직접 호출, 서버 클라이언트 전역 캐시.
- Next.js 16 규칙: `params`/`cookies()` 미`await`, 동적 데이터 컴포넌트가 `<Suspense>` 밖, `middleware.ts` 신규 생성, 불필요한 `"use client"`, 렌더 중 현재 시각 호출로 인한 hydration 불일치.
- 색 하드코딩(디자인 토큰 사용), `cn()` 없는 클래스 병합.

**코드 품질**
- 죽은 코드, 과도하게 긴 컴포넌트, 에러·로딩·빈 상태 누락, 접근성(터치 영역 `min-h-11` 등), 렌더에서의 중복 계산.

## 적용 vs 제안

| 직접 적용 (동작 불변) | 제안만 기록 |
|---|---|
| 중복 추출 + 호출부 교체 | 문구·디자인 등 사용자에게 보이는 변경 |
| 미사용 코드/import 제거 | 스키마·RLS·Server Action 계약·라우트 구조 |
| 토큰·`cn()` 규칙 정리, 라벨/상수 통합 | 의존성 추가·삭제, 대규모 파일 이동 |
| | 확신이 낮은 지적(근거 없으면 싣지 않음) |

낮은 우선순위 이슈(영어 오류 메시지, 아쉬운 UX)는 고치지 말고 `ISSUES.md`에 형식대로 추가한다.

## modified-code.md 형식

프로젝트 루트에 저장하고 실행마다 덮어쓴다(이력은 git). 변경이 없으면 "적용한 변경 없음"과 이유만 쓴다.

```markdown
# 코드 리뷰 결과 (modified-code)

- 실행일: YYYY-MM-DD
- 리뷰 범위: <경로 또는 "전체">
- 검증: `npm run check-all` 통과 / 실패(사유)

## 요약
| 구분 | 건수 |
|---|---|
| 적용한 변경 | N |
| 제안(미적용) | N |
| 수정한 파일 | N |

핵심 변경을 한두 문장으로.

## 적용한 변경
### 1. <변경 제목> — `공통화` | `정합성` | `품질`
- **무엇이 문제였나:** 근거(파일:줄)
- **어떻게 바꿨나:** 한두 문장
- **영향 파일:** `path/a.tsx`, `path/b.tsx`
- **Before / After:** (필요할 때만) 짧은 코드 비교
- **동작 변화:** 없음 / 있다면 무엇

## 제안 (미적용)
| # | 제안 | 이유 | 적용 시 영향 | 우선순위 |
|---|---|---|---|---|

## 변경 파일 목록
| 파일 | 변경 요약 |
|---|---|
```

제안에는 "지금 적용하지 않는 이유"를 반드시 적는다. 숫자와 경로는 실제 diff와 일치해야 한다.

## 채팅 보고

적용·제안 건수, 핵심 변경 1~3개, 검증 결과, 파일 위치만 알린다. `modified-code.md` 내용을 복사하지 않는다.
